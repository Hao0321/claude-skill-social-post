## F29｜再ship 揭露型（「閹割版揭露 → 全公開」，v1.0.2+，6/23 實證）🆕 update 篇救星

**用途**：已 ship 的工具 / skill 要再次推廣（大更新 / 改版 / 補完）時，避開「我又更新了」的無聊與 giveaway 疲勞（R5），改用「之前不完整 → 這次才是真的全公開」框架，製造回訪 + 透明感。

**骨架**（R34 ，、 + ── + vulnerable curiosity hook）：
```
[1. 反差揭露 hook] 昨晚仔細檢查＜工具＞，發現很扯的事 ── ＜舊版竟然是閹割版 / AI 幫我留一手 / 沒做完＞
──
[2. 揭露 + 自嘲] ＜為什麼之前不完整的真實/有趣原因＞，這次重新優化全部公開，一個都不留
──
[3. 再 ship 理由] 到＜版本號＞正式版，載過的回來更新
──
[4. demo > claim] 成果我放留言區自己點
```

**觸發時機**：工具 / skill / repo 出大更新版本，想讓舊用戶回來更新 + 拉新觀眾。

**為何 work**：
1. **hook 三合一**：好奇（蛤？AI 會這樣留一手？）+ 反差（閹割 vs 全公開）+ 自嘲（vulnerable + 有趣）
2. **聰明再 ship 框架**：「之前不完整」製造回訪理由，比「又更新了」強
3. **開源不藏 ethos**（「一個都不留」）+ demo>claim（成果放留言區，R36）
4. **新 intent**（skill 更新故事）避開 giveaway 疲勞（R5）

**實證**：6/23 = 4,549 觀眾 / **54.2% broke** / 22 儲存 / 126 讚（品質高）。

**具體操作**：
1. 揭露要**真實**（真的有舊版缺陷 / 真的補完），不是硬編故事
2. 緊接著可用 R37 value-prop-lead 再推一棒放大（Case 36→38 同工具，38 達 8x）
3. link 放留言區（R25），mild ！！！不過量

**vs F26 / F27**：F26 reveal「私藏作品集」（沒拿出來過）；F27 單品接力（首次 drop）；**F29 是同一個東西的版本迭代再發**（拿出來過但不完整）── 三者是 ship 生命週期不同階段。

**月配額**：跟著大版本更新（一次大 update 一篇，小改別發，連用會變「一直在補洞」觀感）。
**複製度**：4/5
**平台**：FB 主、Thread
